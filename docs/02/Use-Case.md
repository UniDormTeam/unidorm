# Use Case Diagram – UniDorm

## 1. Introduction

نمودار Use Case سامانه UniDorm با هدف نمایش قابلیت‌های اصلی سیستم و نحوه تعامل کاربران با آن طراحی شده است. این نمودار با تمرکز بر نیازمندی‌های نسخه اولیه محصول (Minimum Viable Product - MVP) تهیه شده است.

## 2. MVP Scope

این نمودار صرفاً قابلیت‌های در نظر گرفته‌شده برای نسخه MVP سامانه UniDorm را پوشش می‌دهد و شامل تمام امکانات احتمالی نسخه‌های آینده نیست.

قابلیت‌های اصلی این نسخه عبارت‌اند از:

1. **Appointment Management:** مدیریت و استفاده از سیستم نوبت‌دهی.
2. **Fault Reporting:** ثبت و رسیدگی به گزارش‌های خرابی.
3. **Announcement Management:** ایجاد، ویرایش، حذف و انتشار اطلاعیه‌ها.

قابلیت‌هایی که خارج از محدوده MVP قرار دارند، در نمودار فعلی نمایش داده نشده‌اند و می‌توانند در نسخه‌های بعدی سامانه توسعه داده شوند.

## 3. Actors

در این سیستم پنج Actor تعریف شده است:

| Actor | Description |
|---|---|
| Manager | مدیر سامانه که مسئول مدیریت نوبت‌ها، گزارش‌های خرابی و اطلاعیه‌ها است. |
| Student | دانشجویی که از امکانات سامانه برای ثبت نوبت، گزارش خرابی و مشاهده اطلاعیه‌ها استفاده می‌کند. |
| Facilities Officer | مسئول رسیدگی به گزارش‌های مربوط به تأسیسات. |
| Internet Officer | مسئول رسیدگی به گزارش‌های مربوط به اینترنت. |
| Appointment Resource Officer | مسئول مدیریت منابع و ظرفیت‌های مرتبط با نوبت‌دهی. |

## 4. Use Cases

### 4.1. Appointment Management

این بخش شامل قابلیت‌های مربوط به سیستم نوبت‌دهی است.

| Use Case | Description |
|---|---|
| View Available Appointments | مشاهده نوبت‌های آزاد و قابل رزرو. |
| Book Appointment | ثبت و رزرو نوبت توسط دانشجو. |
| View My Appointments | مشاهده نوبت‌های ثبت‌شده توسط دانشجو. |
| Cancel Appointment | لغو نوبت ثبت‌شده. |
| Manage Appointments | مدیریت نوبت‌ها توسط مدیر. |
| Manage Resource Availability | مدیریت ظرفیت و در دسترس بودن منابع نوبت‌دهی. |

### 4.2. Fault Reporting

این بخش برای ثبت و پیگیری گزارش‌های خرابی در خوابگاه در نظر گرفته شده است.

| Use Case | Description |
|---|---|
| Submit Fault Report | ثبت گزارش خرابی توسط دانشجو. |
| View Fault Report Status | مشاهده وضعیت گزارش خرابی توسط دانشجو. |
| View Fault Reports | مشاهده گزارش‌های ثبت‌شده توسط مدیر. |
| Assign Fault Report | ارجاع گزارش خرابی به مسئول مربوطه توسط مدیر. |
| Handle Fault Report | رسیدگی به گزارش خرابی توسط مسئول مربوطه. |

دو Actor با عنوان Facilities Officer و Internet Officer از Use Case مشترک Handle Fault Report استفاده می‌کنند. هر مسئول متناسب با حوزه کاری خود به گزارش‌های ارجاع‌شده رسیدگی می‌کند.

### 4.3. Announcement Management

این بخش شامل قابلیت‌های مدیریت و انتشار اطلاعیه‌ها است.

| Use Case | Description |
|---|---|
| Create Announcement | ایجاد اطلاعیه جدید توسط مدیر. |
| Edit Announcement | ویرایش اطلاعیه‌های موجود. |
| Delete Announcement | حذف اطلاعیه. |
| Publish Announcement | انتشار اطلاعیه در سامانه. |
| View Announcements | مشاهده اطلاعیه‌های منتشرشده توسط دانشجو. |


## 5. Conclusion

نمودار Use Case سامانه UniDorm نمای کلی از قابلیت‌های اصلی نسخه اولیه محصول (MVP) و نحوه تعامل کاربران با آن‌ها را نمایش می‌دهد. این نمودار سه بخش اصلی نوبت‌دهی، گزارش خرابی و اطلاعیه‌ها را پوشش می‌دهد و به‌عنوان مبنایی برای تحلیل نیازمندی‌ها، طراحی و پیاده‌سازی نسخه اولیه سیستم مورد استفاده قرار می‌گیرد.
