# معماری فنی و برنامه میزبانی UniDorm

## ۱. هدف مستند

این مستند انتخاب‌های فنی پروژه UniDorm، نحوه ارتباط اجزای نرم‌افزار و
برنامه فعلی تیم برای استقرار نسخه MVP را توضیح می‌دهد.

### دلیل انتخاب فناوری‌ها

-   **React:** امکان ساخت رابط کاربری با کامپوننت‌های قابل استفاده مجدد و
    مدیریت بخش‌های مختلف پنل کاربران را فراهم می‌کند.
-   **Django:** چارچوبی ساخت‌یافته برای پیاده‌سازی منطق سمت سرور، مدیریت
    کاربران، اعتبارسنجی و تعامل با پایگاه داده ارائه می‌دهد.
-   **Django REST Framework:** ساخت APIهای مبتنی بر REST را در کنار
    Django ساده‌تر می‌کند و ارتباط استاندارد فرانت‌اند با بک‌اند را ممکن
    می‌سازد.
-   **PostgreSQL:** برای داده‌های رابطه‌ای پروژه، مانند کاربران، سازمان‌ها،
    عضویت‌ها، درخواست‌های تعمیرات و رزروها مناسب است و از روابط و
    محدودیت‌های داده پشتیبانی می‌کند.
-   **JWT:** امکان احراز هویت درخواست‌های API را بدون وابستگی به نگهداری
    نشست سنتی در سمت سرور فراهم می‌کند. نحوه استفاده از Access Token و
    Refresh Token در مستند API تشریح شده است.

## ۳. معماری و نحوه ارتباط اجزا

سامانه از سه بخش اصلی تشکیل می‌شود:

1.  **Frontend (React):** صفحات، فرم‌ها و تعاملات کاربر را نمایش می‌دهد.
2.  **Backend (Django + DRF):** درخواست‌های REST را دریافت می‌کند، هویت و
    سطح دسترسی کاربر را بررسی می‌کند، قوانین اصلی سامانه را اجرا می‌کند و
    داده‌های موردنیاز را می‌خواند یا ذخیره می‌کند.
3.  **Database (PostgreSQL):** اطلاعات سامانه را به‌صورت پایدار نگهداری
    می‌کند.

ارتباط فرانت‌اند و بک‌اند از طریق درخواست‌های HTTP به REST API انجام می‌شود.
فرانت‌اند درخواست را با مسیر و روش مشخص به بک‌اند می‌فرستد؛ بک‌اند پس از
اعتبارسنجی ورودی و بررسی مجوزها، در صورت نیاز با PostgreSQL تعامل می‌کند
و نتیجه را معمولاً در قالب JSON برمی‌گرداند.

``` text
User
  |
  v
React Frontend
  |
  | HTTP Requests / REST API (JSON)
  v
Django + Django REST Framework
  |
  | Database Queries
  v
PostgreSQL
```

در این معماری، React مستقیماً به پایگاه داده متصل نمی‌شود. تمام دسترسی‌ها
به داده از طریق بک‌اند انجام می‌شوند تا قوانین برنامه و مجوزهای کاربران در
سمت سرور کنترل شوند.

## ۴. احراز هویت و کنترل دسترسی

برای احراز هویت کاربران از JWT استفاده می‌شود. پس از ورود موفق، توکن‌های
موردنیاز صادر می‌شوند و فرانت‌اند آن‌ها را در درخواست‌های مجاز به بک‌اند
ارسال می‌کند.

کنترل دسترسی در سمت بک‌اند انجام می‌شود؛ بنابراین صرفاً مخفی‌کردن یک دکمه یا
صفحه در React برای محافظت از عملیات کافی نیست. بک‌اند باید نقش کاربر،
عضویت او در سازمان و مالکیت اطلاعات را بررسی کند.

جزئیات Endpointهای ورود، خروج و تمدید توکن در فایل `API.md` آمده است.

## ۵. برنامه میزبانی و استقرار (Hosting Plan)

### ۵.۱. وضعیت فعلی

در حال حاضر محل نهایی استقرار مشخص نشده است. دو گزینه برای میزبانی بررسی
می‌شوند:

-   **سرور دانشگاه:** در صورت فراهم بودن دسترسی، منابع و امکان تنظیم
    سرویس‌های موردنیاز، از زیرساخت دانشگاه استفاده خواهد شد.
-   **سرور مجازی (VPS) از ارائه‌دهنده ایرانی:** اگر سرور دانشگاه در دسترس
    نباشد یا نیازهای پروژه را برآورده نکند، یک VPS از یکی از
    ارائه‌دهندگان داخلی تهیه می‌شود.

انتخاب نهایی پس از بررسی امکانات، محدودیت‌ها، هزینه و دسترسی به سرور
انجام خواهد شد.

### ۵.۲. دامنه

دامنه `unidorm.ir` برای پروژه تهیه شده است. پس از مشخص‌شدن سرور، تنظیمات
DNS دامنه برای اتصال آن به زیرساخت انتخاب‌شده انجام می‌شود.

### ۵.۳. محل اجرای اجزا

محل نهایی اجرای فرانت‌اند، بک‌اند و پایگاه داده هنوز تعیین نشده است. گزینه
ساده‌تر برای نسخه MVP این است که هر سه جزء روی یک سرور اجرا شوند؛ در این
حالت:

   فایل‌های خروجی نسخه نهایی React از طریق وب‌سرور ارائه می‌شوند.
   برنامه Django با یک سرویس اجرای مناسب در پشت وب‌سرور اجرا می‌شود.

 و PostgreSQL روی همان سرور و با دسترسی محدود به سرویس بک‌اند قرار
    می‌گیرد.

این چیدمان فعلاً یک پیشنهاد برای ساده نگه‌داشتن استقرار اولیه است، نه
تصمیم قطعی. در صورت وجود محدودیت در سرور دانشگاه یا نیازهای امنیتی و
عملیاتی، محل اجرای اجزا می‌تواند جداگانه انتخاب شود.

### ۵.۴. مشخصات منابع سرور

مشخصات زیر صرفاً برآورد اولیه برای شروع بررسی و انتخاب سرور هستند و پس از
مشخص‌شدن تعداد کاربران، امکانات سرور دانشگاه و قیمت ارائه‌دهندگان بازبینی
می‌شوند.

  منبع             مقدار پیشنهادی اولیه
  ---------------- ----------------------
  سیستم‌عامل        Ubuntu Server
  پردازنده         ۲ هسته
  حافظه RAM        ۴ گیگابایت
  فضای ذخیره‌سازی   ۵۰ گیگابایت SSD

این مقادیر تضمین‌کننده ظرفیت نهایی نیستند و باید با منابع واقعی و بار
مورد انتظار پروژه تطبیق داده شوند.

### ۵.۵. هزینه و محدودیت‌ها

هزینه میزبانی در حال حاضر مشخص نیست؛ زیرا هنوز بین سرور دانشگاه و تهیه
VPS تصمیم‌گیری نشده است. در صورت استفاده از سرور دانشگاه، هزینه و
محدودیت‌ها تابع امکانات و سیاست‌های دانشگاه خواهد بود. در صورت تهیه VPS،
هزینه بر اساس ارائه‌دهنده، منابع انتخابی و دوره پرداخت تعیین می‌شود.

پس از انتخاب گزینه نهایی، نام ارائه‌دهنده، مشخصات پلن، هزینه، محدودیت
منابع و مسئولیت نگهداری سرور به این بخش اضافه خواهد شد.

## ۶. ملاحظات استقرار و امنیت

موارد زیر برای زمان استقرار در نظر گرفته می‌شوند:

-   استفاده از HTTPS برای ارتباط امن کاربران با سامانه.
-   تنظیم دامنه و DNS پس از مشخص‌شدن سرور.
-   نگهداری تنظیمات محرمانه و کلیدهای امنیتی در متغیرهای محیطی و خارج از
    کد منبع.
-   محدودکردن دسترسی مستقیم به پایگاه داده و فراهم‌کردن دسترسی آن برای
    بک‌اند.
-   تهیه نسخه پشتیبان منظم از پایگاه داده و بررسی امکان بازیابی آن.
-   تنظیم مجاز بودن مبدأ درخواست‌های فرانت‌اند در بک‌اند (CORS) متناسب با
    دامنه نهایی.

برای اجرای پیشنهادی روی یک سرور لینوکسی، می‌توان از Nginx به‌عنوان وب‌سرور
و Reverse Proxy و از Gunicorn برای اجرای Django استفاده کرد. انتخاب و
تنظیم نهایی این ابزارها در زمان استقرار انجام می‌شود.

## ۷. مراحل کلی استقرار

پس از انتخاب سرور، مراحل کلی استقرار به‌ترتیب زیر خواهد بود:

1.  آماده‌سازی سرور و نصب سیستم‌عامل و بسته‌های موردنیاز.
2.  نصب و پیکربندی PostgreSQL و ایجاد پایگاه داده و کاربر اختصاصی
    برنامه.
3.  تنظیم متغیرهای محیطی و پیکربندی Django برای محیط عملیاتی.
4.  اجرای Migrationها و آماده‌سازی داده‌های اولیه موردنیاز.
5.  اجرای بک‌اند با سرویس مناسب و تنظیم Nginx.
6.  ساخت نسخه نهایی React و قرار دادن فایل‌های خروجی در محل ارائه
    فرانت‌اند.
7.  تنظیم آدرس API در فرانت‌اند و تنظیم CORS در بک‌اند.
8.  اتصال دامنه `unidorm.ir` و فعال‌سازی HTTPS.
9.  بررسی ورود و خروج، سطح دسترسی نقش‌ها، گردش‌کارهای اصلی و ماندگاری
    اطلاعات پس از استقرار.
10. تنظیم و آزمایش پشتیبان‌گیری پایگاه داده.
